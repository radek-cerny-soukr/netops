# Verified platform support

One row per platform or channel the family actually names in its own catalogues. "Verified
end-to-end" means this code reached a real device over the real network and did the real thing
being claimed. "Unit/wire-tested only" or "catalogue only" means the claim rests on a substituted
client, a fixture, or a dump taken by something other than this code - not on this code meeting a
device. Every cell below is filled from a statement already written down elsewhere in this
repository; follow the links for the exact wording, the exact byte counts and the exact dates.

The later [T-067 functional series](lab-measurements-2026-09-25.md#functional-and-fault-tests-t-067) adds actual ICMP/HTTP, VLAN/trunk isolation, inter-VLAN routing, DHCP acquisition, controlled SSH/data outages, cEOS persistence and cross-host cEOS-Nexus traffic on the candidate. Nexus LLDP returned a real neighbour with the native VLAN allowed at both trunk ends; the exit-244 catalogue row above remains the earlier observation. The follow-up Auditor run used a password credential and found the same missing-syslog rule; snapshot equality was checked only within the original key-authenticated comparison. T-067 covers four overlapping virtual instances, not four additional image variants. Its 40 PASS / 16 FAIL records include setup, repetitions and cleanup, not a product pass rate. Outbound cEOS SVI ACL attachment was rejected; Admin execution, protocol convergence and redundant failover were not measured by that series.

What was learned, and what changed because of it:

- **The host key scan exhausted small VTY pools.** `ssh-keyscan` without `-t` opens one connection per key type at once. An image with five VTY lines (`line vty 0 4`, a common IOS default) still had those sessions closing when the real connection arrived and reset it. Reproduced from the runner host: a full scan followed at once by `ssh` was refused, the same scan followed by a three-second pause, or a single-type scan followed at once by `ssh`, was not. From an OpenSSH 9.2p1 host the released code failed one call in five; through the runner it failed every call. Core now asks for `ed25519`, then `ecdsa`, then `rsa`, one connection at a time, and stops at the pinned key; the three attempts share the original timeout. The fixed scan was run against FortiOS 7.6.7 and 8.0 firewalls, an ExtremeXOS 33.7.1 switch (offers only `ssh-rsa`), cEOS and vJunos, and found the pinned key on each.
- **`ssh-keyscan -t <type>` exits 1 when the device has no key of that type.** The first version of the fix treated that as a failed scan and passed its unit tests, which modelled an empty answer with status 0; the live run against an RSA-only device caught it. An empty answer now moves on to the next type, and the tests model the real status.
- **IOS, IOS-XE and Junos refuse with exit status 0.** IOS and IOS-XE answer an unknown command, and a command above the account's privilege, with `Line has invalid autocommand "<command>"`; Junos with `error: syntax error, ...`, `error: unknown command: ...` or `error: permission denied: ...`; EOS with `% Invalid input ... at line N` and exit status 1. The helper returned these as successful reads. The classifier now reports them as `device_cli_error`, with the output kept for the caller, as it already did for FortiOS and ExtremeXOS.
- **Interface grammar was Catalyst grammar.** IOL names its ports `Ethernet0/0`, which neither `cisco_xe` nor `cisco_ios` accepted, so no physical port of these images could be enrolled. Both now accept `Ethernet<slot>/<port>` (slot and port 0-15), the naming of Cisco router ports and of the IOL images; `cisco_ios` still refuses `GigabitEthernet0/0`.
- **Classic IOS images speak only SHA-1 key exchange.** The new per-device profile `legacy_ssh: "rsa-sha1-dh14"` adds exactly `diffie-hellman-group14-sha1` to the `rsa-sha1` options for the device that names it; every other device keeps SHA-1 key exchange off. `ssh-keyscan` cannot offer a SHA-1 key exchange, so the host key of such a device is read by one `ssh` connection that authenticates with nothing, into a private temporary known-hosts file, and checked against the pin as before.
- **OpenSSH 10.0p2 `ssh-keyscan` writes its banner comment to standard output.** With `-t` for a type the device lacks it prints `# host SSH-2.0-...` on stdout and exits 1; 9.2p1 wrote the comment to stderr. The first candidate took that comment for an answer with a failing status and refused IOS-XE and NX-OS devices whose only key is RSA, every time through the runner; a type now counts only when the answer holds a line that is not a comment.
- **NX-OS refuses with a non-zero exit status.** `Syntax error while parsing '...'` (16) for an unknown command, and for HSRP, VRRP and vPC commands while the feature is disabled; `% Permission denied for the role` (30) for a command above the role. Both are now `device_cli_error`.

Not measured: NX-OS 10.x (the catalogue baseline; the lab has 9.3(12)), a Junos routing platform, AAA or TACACS command authorization on any of these platforms, and the fixes in a release build.

## Admin 0.2.3 and Auditor 0.2.8 validation, 26 September 2026

## What "verified" does not cover here

- **`ruckus_unleashed` cannot have a read-only account.** Measured 20 September 2026: the device's
  configuration context has no command that creates a second administrator or assigns a role, so an
  enrollment always carries the one administrator. Only an external authentication server with a
  restricted role remains unmeasured.
- **Cisco IOS, IOS-XE, NX-OS, Arista EOS, Junos and Junos ELS are measured on virtual images only** (25 September 2026, see [Live lab measurements](#live-lab-measurements-25-september-2026)); no physical device of these vendors has been measured.
  Linux is live-verified only for `kernel` and `hostname`; the other Linux queries remain wire-simulated.
  Ruckus has live wire measurements but no verified read-only account model.
- A platform's row here can go stale exactly like any other measured fact: a firmware upgrade, a new
  catalogue command, or a changed AAA policy can outdate the specific numbers cited without changing
  this page. Treat every cell as dated evidence, not a standing guarantee, and follow its link.
