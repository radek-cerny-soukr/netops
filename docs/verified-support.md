# Verified platform support

One row per platform or channel the family actually names in its own catalogues. "Verified
end-to-end" means this code reached a real device over the real network and did the real thing
being claimed. "Unit/wire-tested only" or "catalogue only" means the claim rests on a substituted
client, a fixture, or a dump taken by something other than this code - not on this code meeting a
device. Every cell below is filled from a statement already written down elsewhere in this
repository; follow the links for the exact wording, the exact byte counts and the exact dates.

## Helper 0.3.4 additions: direct CLI evidence

The earlier rows describe their dated catalogue snapshots, not all queries added since. Helper 0.3.4 adds two EXOS queries (49 total) and six FortiOS queries (46 total). Tests validate their syntax, inventory boundaries, proxy authorization and simulated output handling. The live observations below used direct SSH CLI calls on 20-21 September 2026; they do not establish end-to-end MCP support for these eight additions.

| Added queries | Observed behavior | Limits |
| --- | --- | --- |
| EXOS `vlan_details`, `dhcp_snooping_entries` | EXOS 33.7.1: three VLAN details checked through exec and interactive SSH, valid status 250; DHCP binding table returned status 0 | Read-only CLI observations; revalidate the deployed AAA path |
| FortiOS `certificate_details` | FortiOS 8.0.0: read-only account returned public metadata and expiry | No private-key export; no end-to-end MCP claim |
| FortiOS `managed_switch_status`, `managed_switch_poe`, `managed_switch_mac`, `managed_switch_lldp` | FortiOS 8.0.1: controller returned data for an enrolled switch | Administrator account; restricted-profile permissions remain unverified |
| FortiOS `managed_switch_stacking` | FortiOS 8.0.1: feature refusal -7622 on a non-stacking model | No positive hardware validation; refusal is a failed CLI read |

See the exact templates and source references for [EXOS](../components/netops-helper/docs/vendor-cli-references/extreme-switch-engine.md#scoped-diagnostic-queries) and [FortiOS](../components/netops-helper/docs/vendor-cli-references/fortinet-fortios.md#scoped-diagnostic-queries). Managed-switch reads go through the FortiGate controller; no direct switch SSH connection or new FortiAP query is required. The helper's requirement for a separately verified read-only target identity remains unchanged.

## What "verified" does not cover here

- **`ruckus_unleashed` cannot have a read-only account.** Measured 20 September 2026: the device's
  configuration context has no command that creates a second administrator or assigns a role, so an
  enrollment always carries the one administrator. Only an external authentication server with a
  restricted role remains unmeasured.
- **Cisco IOS, IOS-XE, NX-OS, Arista EOS, Junos and Junos ELS remain catalogue and wire-simulated only.**
  Linux is live-verified only for `kernel` and `hostname`; the other Linux queries remain wire-simulated.
  Ruckus has live wire measurements but no verified read-only account model.
- A platform's row here can go stale exactly like any other measured fact: a firmware upgrade, a new
  catalogue command, or a changed AAA policy can outdate the specific numbers cited without changing
  this page. Treat every cell as dated evidence, not a standing guarantee, and follow its link.
