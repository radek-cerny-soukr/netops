# NetOps 1.0 architecture

One product and one container contain Core, Helper, Auditor and Admin. Their existing engines and measured device contracts are retained. All roles share the hashed production closure in `requirements.lock`, initially FastMCP 4.0.5 and MCP 2.2.0. Every change to dependency versions must resolve and test the entire closure again.

The image uses a pinned multiarch Python 3.14.9 / Alpine 3.24 base. Gateway, Helper, Auditor and Admin have distinct UID/GID pairs 51000 through 51003. A short bootstrap prepares only declared directories, starts role processes, removes all bounding capabilities and becomes the unprivileged gateway. The long-running gateway and role processes have empty supplementary groups, zero effective/permitted/inheritable/ambient/bounding capabilities and no-new-privileges. The Docker healthcheck (`netops health`) and one-off operator commands run with `docker compose run` start briefly as root with the capability set declared in Compose: the healthcheck, `configure`, `ca rotate`, `audit recover` and the `admin`/`auditor` commands drop to the gateway or role UID before their work, while `init`, `ca` export, `token`, `connection` and the other `audit` reads run as root until they exit. IPC authenticates peer UID in both directions. A process holding the state instance lock prevents a second instance from starting against the same data. The runtime and role configuration workflows reject any other product version or state schema before starting workers or installing inputs. The one exception is the state of the immediately preceding release (1.0.1 for NetOps 1.0.2): the first `serve` start of the new release reads the gateway configuration again after taking the instance lock and atomically replaces only its recorded product version, then records the previous and the new version in the `instance_start` audit event. `init`, `token rotate` and the operator commands that take the instance lock (`configure`, `ca rotate`, `audit recover` and the `admin`/`auditor` workflows) never convert; over state that is not yet converted they refuse and ask for a start of the new release first, while the read-only commands `connection`, `ca` export, `token show` and the `audit` reads keep working. No other migration and no downgrade is attempted. The runtime never mounts the Docker socket or uses host networking.

The native image entrypoint preserves a pending SIGTERM across exec before Python startup. The Python launcher installs its stop handler and unblocks the signal before importing the CLI or starting role workers. The native entrypoint execs Python directly and leaves no supervisor process; it blocks SIGTERM only for serve, while other commands keep their normal startup. Startup cancellation joins its owned role-list RPC before exit; once gateway startup owns the stop signal, normal audit shutdown applies.

The HTTPS gateway uses the existing FastMCP Streamable HTTP implementation with stateless JSON responses. Every supported request, notification, response and connection boundary is audited. Requests are durable before dispatch; responses are durable before delivery. A failed response audit reports that the operation may have completed and forbids automatic retry. An incomplete final local audit record, for example after power loss during a write, blocks following operations: the gateway refuses to start and the healthcheck reports it. `netops audit recover`, run while the instance is stopped, moves only the incomplete trailing bytes of each segment to a private quarantine file in the audit directory, records the recovery in the audit and changes nothing when a complete record is invalid JSON. A syslog queue is bounded and durable before dispatch; TLS/TCP transmission does not prove receiver persistence. The forwarder sends queued records in batches of up to 512 records or 16 MiB over one TLS connection, outside the audit write lock, removes them only after the transport hand-over of the complete batch described under [Syslog delivery](#syslog-delivery), retries with backoff and reports a failing receiver once in the gateway log. Stateless HTTP does not offer server-originated long-lived SSE sessions or automatic replay of writes.

For local audit, the writer holds an exclusive segment lock through the complete write and fsync. The live health check uses a nonblocking shared lock: a locked segment is being written and is not classified as a crashed incomplete record. An unlocked incomplete record still fails health and startup; offline recovery remains explicit. A writer stuck while holding its lock is not detected by this check; health still separately verifies TLS readiness of the gateway and readiness of the role workers.

Cancellation does not abandon an audit commit: the handler waits for redaction and the durable write before propagating cancellation. A request cancelled after its audit begins records an interrupted outcome and connection end when audit storage remains available. A connection_end with delivery committed-before-send records the boundary before network delivery; if sending is then cancelled, the same correlation may also have an interrupted connection_end. Neither record proves client receipt. An interrupted dispatched operation may have completed and must never be retried automatically.

At the gateway, an authenticated request uses a single shared lane if it has a Transfer-Encoding header; duplicate, empty, non-decimal or oversized Content-Length values (more than 10 bytes); a declared body above 65536 bytes; or no Content-Length unless it is GET, HEAD or OPTIONS over HTTP/1.0 or HTTP/1.1. The lane covers receiving, auditing and dispatch. All admitted requests, including that lane, share 16 operation slots; connections waiting for the lane do not hold a slot. A large request can therefore wait behind another large request across roles while smaller correctly framed requests can use the remaining slots.

An authenticated connection cancelled while waiting for admission records admission_cancelled and connection_end with delivery not_started. If it is cancelled while its body is still being read, request_body_cancelled records that the body is incomplete, the received byte count and that no operation executed, followed by connection_end. These cancellation records contain method and path but no headers, body fragments or inferred MCP parameters. They do not claim that a complete request was received. An admitted request has 60 seconds to deliver its complete body; when that deadline expires, the gateway records rejection with reason body_timeout, complete_body false, the received byte count and operation_executed false, with method and path but no headers or body fragments, answers HTTP 408 with Connection: close and releases the slot and, for a large request, the lane without dispatch.

After a complete authenticated large MCP request is durably audited, the gateway checks for an already observable client disconnect before tool validation or dispatch. The observation has a fifty-millisecond timeout; any cancelled receive call remains owned until it finishes, before dispatch or release of the admission slot. An observed disconnect retains the full redacted request, then records client_disconnect with phase before_dispatch, complete_body true, the received byte count and operation_executed false, followed by connection_end with delivery not_started. Cancellation during this check follows the existing request/interrupted/connection_end path and reports that no operation was dispatched. This check does not prove eventual client receipt.

Shutdown waits for admitted handlers, cancelled admission waiters and their audit records before recording instance_stop. After the server shutdown grace period, cleanup has an additional twenty-second budget. If cleanup fails or that budget expires, the process reports incomplete audit shutdown and exits with status 1; this is a crash, not proof of completed operations. Inspect the durable audit and actual device state before any retry, and use the stopped-instance audit recovery procedure if a local record is incomplete. A stop record does not itself prove client delivery or a later successful filesystem sync. In syslog mode a batch delivery in progress at stop counts toward that budget; its records stay queued until delivery completes and may be delivered again after restart. The final instance_stop record is appended after the forwarder stops and remains in the durable syslog queue until forwarding resumes on a subsequent start.

Audit JSON contains parsed protocol content, explicit redaction paths and a representation label. It is not a raw byte transcript. Known token values, secret-bearing fields, private-key blocks and documented password forms are redacted. Worker-side credential values are removed before crossing into the gateway. Device output remains sensitive. Audit output escapes terminal controls. Local retention defaults to seven days within a 256 MiB budget and 16 MiB segments; the syslog queue blocks new operations when its budget is exhausted. Disk budgets must be checked against measured workload before deployment.

The Helper bridge retains enrollment, device host-key checks, per-target authorization, rate limits and output sanitization. Credentials are loaded only by the Helper worker. The old host firewall/egress setup is absent. SNMPv2c and FTP/FTPS operations are explicitly refused in the SSH/HTTPS-only default profile. ICMP uses unprivileged datagram sockets. Admin and Auditor use their existing engines and protected role data. No network device is enrolled implicitly.

Each role uses its private state directory as its home. The Helper keeps its existing bounded operation-summary recorder in its own private operations.jsonl (2 MB segments, five retained segments); it cannot read or alter the gateway transport audit. These summaries supplement the mandatory gateway request/response records and do not replace them. Operator workflows use the same role-owned home and permissions. Offline Admin workflows run with the gateway stopped: an allowlisted workflow name is durably recorded by a short gateway-UID preflight process, then the Admin engine uses its private operation log and change journal. Role configuration and Auditor snapshot/policy imports also require this gateway-UID intent before reading their input. Only allowlisted workflow names are recorded, without file names, command arguments or input values. This intent record is not a gateway MCP response or a completion receipt. Audit preflight and private-log write failures refuse device writes. Local preflight detects an incomplete final record but does not revalidate complete historical JSONL records or prove freedom from privileged tampering.

The instance CA is private, constrained to the configured DNS subtree, with all IPv4/IPv6 names explicitly excluded and stored outside the image. The server leaf lasts seven days and renews with the existing server key, avoiding a partially replaced key/certificate pair. The instance CA is valid for 730 days from init or its last rotation. Renewal of the server certificate is attempted when it has two days or less left; once the CA expires within seven days, that renewal is refused and the instance stops, and with `restart: unless-stopped` every restart fails the same way. When the running instance stops for this reason, its container exits with status 0; each later start is refused and exits with status 2. `connection` and the gateway log warn from 30 days before expiry, and the healthcheck reports the instance unhealthy from 14 days. `netops ca rotate`, run while the instance is stopped, records its start in the mandatory audit before any change, issues a new CA under the same name constraints and a new server key and certificate, keeps the previous pair in a private retired directory of the state volume and records completion; the token and role data are unchanged. The gateway and the healthcheck verify that the CA and server key and certificate files match before serving, so an interrupted rotation stops the instance with guidance to rotate again. Clients must then trust the new CA; clients that trust only the previous CA refuse the connection. Token rotation is an operator action; authorization is rechecked before response delivery. Init never prints the token and preserves existing identities on repeat.

Functional qualification uses the actual released image: CI suites, including device operations, on amd64 and arm64; quickstart installation, MCP clients, audit and restart on every supported host family; and the upgrade from the previous release on amd64, arm64 and Fedora when the release changes stored state. Import or SDK smoke tests are only their stated evidence scope. Confirmed relevant vulnerabilities, missing tests and failed installation paths block release.

## Unauthenticated request rejection

The gateway checks the bearer token and HTTPS before reading any request body or acquiring an operation slot. Rejected clients cannot consume the durable operation-audit budget or rotate its history. Bodies, headers and paths are intentionally not retained. Denials of requests that reach the gateway application are aggregated into a separate fixed-size private rejection summary (rejections.json), exposed by netops audit stats: `authentication_required` counts a missing or wrong token and `https_required` an authenticated request that did not arrive over HTTPS. A connection that fails before the application is not counted: plain HTTP sent to the HTTPS port fails in the TLS layer and leaves no line in `docker compose logs netops`, and an invalid HTTP request sent inside TLS is logged there as `WARNING:  Invalid HTTP request received.`. In the summary, the first denial is persisted immediately, later counts at most once per 60 seconds and on graceful shutdown. A crash can lose the latest 60 seconds of denial counts. The summary is local and does not claim a complete per-request transcript or independent syslog protection. Supported authenticated MCP messages continue to receive complete redacted request/response audit with durable ordering.

## Syslog delivery

Every audit record, including a small one, is encoded as numbered parts. The persistent 32-lowercase-hex UUID in its queued filename is the record identity across retries. Original queued bytes, including the final LF, are split into consecutive 1024-byte chunks; the final chunk contains 1–1024 bytes. The existing maximum record remains 8 MiB, at most 8192 parts indexed from zero.

Each RFC5424 message has the fixed 55-byte UTC header and a compact ASCII JSON MSG with exactly `schema`, `record_id`, `part`, `parts`, `sha256` and `data_b64`. The schema is `netops-syslog-part/1`; SHA256 covers the complete original record and standard padded base64 carries each raw chunk. The largest encoded message is 1618 bytes including its header, below the enforced 2048-byte cap. RFC5425 framing adds the decimal message length and one space. The sender calculates its timeout from all actual framed bytes, including headers, envelopes, base64 and count prefixes.

A batch is handed over when TLS verifies the receiver, every frame is passed without error and NetOps attempts orderly TLS closure. The existing tolerated TCP EOF after our close_notify remains. This is transport hand-over; it provides no receiver application or durable-storage acknowledgement. A connection, certificate, send, reset or timeout failure retains every complete queued record in the batch, including records whose prefix may already have arrived. A retry resends the complete records with the same UUID, part mapping and SHA; its timestamp may change. Only successful transport hand-over removes the whole batch. The existing disk budget, backoff and admission rules remain.

A receiver must filter RFC5424 APP-NAME exactly equal to `netops` into a dedicated append-only part archive, preserving each original MSG byte string followed by one LF. Keep other applications and older NetOps 1.0 full-record archives separately. NetOps must have no authority to change retained receiver data. Preserve existing archives during cutover; configure and verify the new archive before the first 1.0.1 start, which also sends any queued 1.0.0 records in the part format. The receiver must discard an incomplete frame left by a restart or a connection reset instead of storing it: a partial line stored before a record is complete makes the reconstruction of every record that completes only after that line fail with exit 2, and records completed earlier report `late_invalid` (exit 3); a full NetOps 1.0 message stored in the part archive by mistake has the same effect.

Reconstruction selects one explicit ID and follows receiver archive line order. Before completion, conflicting parts or metadata and invalid/unattributable rows are errors. The first complete consistent set with a valid whole SHA freezes the original byte sequence immediately, at its completion line. Later selected conflicts or invalid/unattributable rows produce typed line warnings and cannot change those bytes. Valid identical retries are idempotent, including another compact key order. A unique string ID belonging to another record is isolated before validating its other fields; duplicate, missing or non-string IDs cannot be attributed. Selected envelopes require bounded compact ASCII, exact fields and types, including bool not being an integer.

The offline command `netops audit reassemble --record-id <32-lowercase-hex>` reads only MSG JSON-lines from stdin and requires no initialized instance, configuration, vault or service. It continues to EOF after freezing, emits the original bytes only after successful input consumption, and does not alter the source archive. Exit 0 means clean reconstruction; exit 3 emits the same frozen bytes plus warnings; exit 2 emits no record bytes on an argument, validation or input-read error, even after completion or warnings. A stdout write failure also ends with exit 2 and can leave a partial new output file; preserve that file and the original archive for inspection.

Warnings are compact ASCII JSON-lines on stderr with exactly `schema`, `code` and `line_number`. Schema is `netops-syslog-reassembly-warning/1`; codes are `late_conflict` for a valid selected part inconsistent with the frozen set and `late_invalid` for a later invalid/unattributable row. Original line numbers and archive order are retained. Errors include the stable `netops: reassembly_argument_error line_0`, `netops: reassembly_validation_error line_N` or `netops: reassembly_read_error after_line_N` prefix. Only missing/incomplete EOF uses `reassembly_validation_error after_line_N`; a wrong whole SHA fails at the completion line, even if it is the last line. Read locations count successfully consumed original input lines; no operating-system error text is copied.

The Python `decode_messages(messages, record_id, *, on_warning=None)` API still returns bytes. An optional callback receives `ReassemblyWarning(code, line_number)`; without it the bytes are preserved but the caller does not collect warnings. Callback and input-iterator exceptions propagate unchanged. CLI always installs its callback and stores only a warning boolean, not an unbounded warning list.

F20/F21 remain unchanged: records are not silently truncated, and later appended conflicting data cannot invalidate a record already accepted by an independent receiver whose archive NetOps cannot modify. SHA detects damage, not the authenticity of data controlled before completion. Events suppressed before sending cannot be detected from this archive.

Native E2E checks on arm64 and amd64 verified that the actual storage of default-limit rsyslog 8.2504 and 8.2512 with the gtls and the ossl driver and of syslog-ng 4.12 preserves the original MSG+LF, with each receiver running in a container; receivers installed as host services were not part of these checks. Unit framing/reassembly tests establish neither receiver storage fidelity nor durable acknowledgement. No 9 MiB maxMessageSize/MaxFrameSize workaround is required by the new bounded sender. The old 1.0 enlarged-limit receiver evidence remains historical.

For rsyslog with the gtls driver, this TLS/MSG-only configuration uses the existing certificate locations and default size limits:

~~~
global(DefaultNetstreamDriver="gtls"
       DefaultNetstreamDriverCAFile="/etc/rsyslog.d/netops-tls/ca.pem"
       DefaultNetstreamDriverCertFile="/etc/rsyslog.d/netops-tls/srv.pem"
       DefaultNetstreamDriverKeyFile="/etc/rsyslog.d/netops-tls/srv.key")
module(load="imtcp" StreamDriver.Name="gtls" StreamDriver.Mode="1" StreamDriver.AuthMode="anon")
template(name="netopsmsg" type="string" string="%msg%\n")
ruleset(name="netopsparts") {
  if $app-name == "netops" then {
    action(type="omfile" file="/var/log/netops-audit-parts.jsonl" template="netopsmsg" fileCreateMode="0640")
  }
}
input(type="imtcp" port="6514" ruleset="netopsparts")
~~~

For syslog-ng, this complete configuration file keeps the default size limits:

~~~
@version: 4.12
source s_tls6514 {
  syslog(transport("tls") port(6514)
    tls(key-file("/etc/syslog-ng/netops-tls/srv.key") cert-file("/etc/syslog-ng/netops-tls/srv.pem") peer-verify(optional-untrusted)));
};
filter f_netops { "${PROGRAM}" eq "netops"; };
destination d_netops_parts { file("/var/log/netops-audit-parts.jsonl" template("${MSG}\n") perm(0640)); };
log { source(s_tls6514); filter(f_netops); destination(d_netops_parts); };
~~~

Set `@version` to the installed syslog-ng version and verify the stored bytes again.

Verify the actual stored bytes, including any parser-added leading whitespace, against the sender MSG before using this template. A template example or syntax check is not that evidence. Keep the original archive unchanged if verification fails; do not trim or normalize it to manufacture a valid part archive. The receiver certificate must match the configured DNS host; for a private CA supply its public certificate as `ca_pem` through `configure syslog`. The previously observed Ubuntu AppArmor certificate-directory restrictions still apply.

Check the receiver's effective service identity after privilege drop. Its certificate directory needs mode 0750 owned by root and the service group; the CA/certificate/key files need 0640 with the same ownership; the new archive needs 0640 owned by the service account/group. Parents must permit traversal, the daemon must read its TLS material and append its own archive, and NetOps must have no authority to alter retained receiver data. Preserve existing archives while adjusting ownership. Validate configuration and actual TLS/storage behavior as that service identity before relying on external audit protection.

## Operation outcomes

The common MCP boundary preserves structured results and marks refused/failed operations with `isError: true`. Helper `ok: false`, Admin rejected/unknown/reverted/revert-failed execution outcomes, failed readiness and unknown operation lookups are errors. Successful `admin_status` reads of previously failed operations and Auditor queries with findings remain successful queries. Unknown writes must be investigated using request/change identity and actual device state, never retried automatically.

Only root metadata declares the netops distribution/version and production dependency closure. Component directories are internal engines with regression tests and API references; their test support fixtures are not deployable components. Historical standalone metadata, installation procedures, images and SBOMs are archived.

## Helper operation summaries

These private engine records supplement the mandatory gateway audit; they cannot replace or modify it. A device operation records `status: "started"` before execution, then `status: "ok"` on normal completion. After an exception, a `status: "failed"` record carries `detail` with the exception type, never its credential-bearing text. An operation_id correlates the two records. The bounded recorder rotates mode-0600 segments inside the Helper private directory. A logical diagnostic refusal returned as data can complete the internal call; its explicit failure is still marked as an error at the public MCP boundary.
