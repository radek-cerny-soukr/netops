# NetOps changelog

## 1.0.7 - 2026-11-10

- Correlate late ARP/ND MACs against saved endpoint MAC tables and reuse auxiliary captures; expose per-alias read caps, cache failed hostname supplements and avoid ownership retries after transport failures. Preserve FortiSwitch all-VLAN configuration with explicit FortiLink context, clear NX-OS connected/local IP gateways and return only active Junos detail routes, consistently with whole-table reads.
- Clarify that Auditor exit 3 is driven by required rule coverage, not every export visibility limitation: networking can be actionable while an unrelated user-area limitation can permit exit 0; retain separate export metadata checks.

- Scale endpoint location to 64 enrolled targets with eight concurrent device readers, a shared deadline and explicit unfinished-target coverage while preserving audited read-only verdicts.

### Tool-result review corrections

- Bound `switch_read` and REST Wi-Fi responses by `limit` (1–500), record `offset` (0–8,000,000) and `max_bytes` (1,000–48,000), with matching `inputSchema` and proxy validation. Return full/returned counts, `has_more` and `next`; unknown lines are paged too. Oversized rows return `result_too_large`. Record pages perform fresh reads charged to the normal budget; filters, joins and summaries precede paging. `wifi_rogue` shares its limit across rogue and interfering lists.
- Preserve session `RestoreUnverified` and `ScopeRefused` in `triage_flow` as structured `restore_unverified` / `scope_refused` failures with `failed_step`, missing evidence and cleanup guidance. Stop `locate_endpoint` on audit persistence failure; worker failure, timeout and audit failures are `ok: false` with stable error codes.
- Return `-32602` with `data.field: ip` for a route request without a required IP, including FortiOS. A `switch_read` protocol that is not configured returns valid `not_applicable`, `ok: true`, MCP `isError: false`; triage still marks missing required evidence incomplete.
- REST Wi-Fi error codes distinguish TLS/pin, 401 authentication, 403 authorization, timeout, HTTP 5xx, other HTTP, invalid JSON, nonfinite numbers, invalid envelope, response size/encoding and configuration from transport failure. Keep coarse `error_subcode` compatibility for existing triage clients; never return response bodies or raw exceptions.
- Document the 200-line log window for EXOS, IOS/IOS XE, NX-OS, EOS and Junos/ELS, including `line_limit` / `log_line_limit` and the possibly absent IOS logging header. Endpoint location reserves `min(40, helper.rate_limit.requests, 7 + exos + vlan_reads + managed_reads * managed_switches)` reads per alias. `exos` is 1 on EXOS, otherwise 0; `vlan_reads` is 1 when the profile's port-VLAN query is enabled, plus 1 on campus profiles (IOS/IOS XE/NX-OS/EOS) or EXOS for its join. `managed_reads` is 2 (MAC/LLDP), plus 1 with FortiOS `managed_switch_port_stats`, plus 2 when both `managed_switch_port_vlans` and `interface_vlan_ids` are enabled. The worker caps actual reads per alias at that reservation, including identity and joins; exhaustion returns incomplete coverage with `target_read_limit`. The reservation permits a call to start under the default 30-request limit, but does not guarantee completion. FortiOS connection starts on one FortiGate are at least 5 seconds apart; at the observed roughly 5.6 seconds per read, about ten reads fit the 59.5-second deadline. An IP lookup with all edge queries needs at least N + 6 reads for N managed switches when only one switch needs edge details: roughly four switches can complete under these conditions. Larger sites, including twelve or thirty switches, return partial findings with incomplete coverage when the deadline or read limit is reached; startup time, latency and additional matched switches can reduce this capacity. Unused reservations are not refunded: a reservation of 30 blocks subsequent calls to that alias for the rest of its 60-second rate window, even if fewer reads run. Each alias uses its own total `rate_limit`, without the triage sublimit; if any alias lacks the reservation the whole call is refused with `rate_limit` and no alias is charged. Explain the deliberate one-call arbitrary IPv4 flow-lookup scope and the additional enrollment required for session reads.
- Release notes now call out the existing `tls_probe.unverified_certificate` / restricted `pin_match` response change, `page_changed_by_redaction`, `ssh_pagination_snapshot_required`, and private per-target SSH serialization/spacing shared by Helper and endpoint worker.

### Changed

- Password SSH authentication of the shared Core transport (Helper, Admin writes and Auditor collection; command, terminal and SFTP) tries `password` first and then keyboard-interactive, so EOS and Junos password logins work. The packaged and the temporary askpass program answer only a password prompt, once per connection; OTP/MFA, host-key questions and repeated password prompts fail closed (an OTP after an accepted password is reported as unsupported, not as a refused credential), and a server-chosen `Token's password:` is not answered. The temporary askpass script runs under `<python> -I` and no longer needs `python3` in `PATH`. Host-key pinning is unchanged. Known limitation: with a wrong password, a device offering both methods can count two failed authentications for one connection, which may count under its lockout policy; this softens the 1.0.1 one-attempt rule.
- The per-target `rate_limit` caps manual and triage reads together, and the triage tools have a sublimit of the same size. A triage reserves its planned reads against both budgets atomically: `triage_health` 10, `triage_routing` 5, `triage_vpn` 4, `triage_slb` 21, `triage_flow` 5 and `wifi_triage` 7 (15 with an enrolled REST token); one `triage_slb` leaves 9 manual requests in the default 30-request window. `switch_read` charges one request (two for a Junos ELS `mac_entry` with the `vlans` join) and `locate_endpoint` its per-target reservation on every named target, all or none. `target_scope` and `helper_status` report the total as `rate_limit` and the triage subset as `triage_rate_limit`.
- `ssh_read` checks the live FortiOS/FortiADC product identity before every fresh read; confirmed identities are never cached and `system_status` itself is the live probe. Measured on a FortiGate-80F 8.0.2: a fresh query takes 8-10 s, including two SSH connections (2.9 s each, 2.2 s of each checking the password) and the five-second connection spacing. The client adds no prompt, end-of-file or fixed-timeout wait; host-key scan caching and the triage connection spacing stay unchanged.
- FortiOS exec reads and the exec reads of the EXOS, IOS/IOS XE, NX-OS, EOS and Junos profiles (also behind `switch_read` and `locate_endpoint`) replace known secret literals (original, LF and carriage-return-free forms, longest first) before and after CRLF-to-LF normalization. `switch_read` and `locate_endpoint` redact the complete device output with every known target, session and transport secret before parsing, like `ssh_read`. `schema_read` keeps configuration syntax intact for parsing and redacts its report structurally, preserving password attributes and accepting quoted values such as `token=abc`.
- Routing triage accepts FortiGate-60F 7.6.8 build 3744 and FortiGate-80F 8.0.2 build 0251 only. The FortiGate-80F was read live (route, policy routes, SD-WAN, ARP) and its outputs are test fixtures; the route parser reads FortiOS 8.0.2 output (`VRF=default(0)`, several routes of one prefix), a SD-WAN member shown as `<interface>/<name>` is matched to the next-hop interface, and the result reports `vdom_mode`.

### Security

- NetOps versions up to and including 1.0.6 can disclose a known session or transport secret through `ssh_read` or `schema_read` when a device prints that value across a page boundary: a client can reconstruct it from two pages. Version 1.0.7 redacts all known target, session and transport secrets over the complete output in the engine before hashing and pagination, using the existing private proxy-to-server handoff; the internal redaction context is absent from public tool schemas and cannot be supplied by clients. Response redaction and the page-change guard remain as additional checks. Upgrade to 1.0.7 and restart paged reads at offset 0.

- Known 1.0.1 limitation: the separate Helper SSH proxy to a runner host keeps both keyboard-interactive and password authentication. - Known 1.0.1 syslog limitation: the whole-record SHA-256 detects damaged or incomplete part archives but does not prove the authenticity of data controlled before the record was complete, and events suppressed before sending cannot be detected from the receiver archive.

## 1.0.0 - 2026-10-17

- Combine Core, Helper, Auditor and Admin in one Docker product with one dependency closure and product version.
- Provide one token-protected HTTPS Streamable HTTP MCP endpoint; no bundled AI clients.
- Isolate role processes and credentials using distinct UID, authenticated local IPC and an unprivileged steady-state runtime.
- Persist every supported request before dispatch and its response before delivery; refuse new operations when the audit cannot be committed.
- Support bounded TLS syslog forwarding or explicit local audit with rotation, retention and safe terminal output. Mark credential redaction visibly.
- Keep audit pending results independent of segment traversal order after backup and restore, including interrupted operations with a recorded response.
- Initialize an instance CA, automatically renewed server certificates, token and protected role data. Preserve identities on repeated init.
- Rotate the instance CA with `netops ca rotate` while the instance is stopped; warn from 30 days before expiry and report unhealthy from 14 days.
- Recover an interrupted local audit write with `netops audit recover`, which quarantines only the incomplete trailing bytes; audit reads, startup and the healthcheck name the condition.
- Refuse concurrent instances and operator configuration over live state; retain safeguards and explicit handling of unknown writes.
- Report refused, failed or uncertain operations as MCP errors (`isError`) and keep their full result content.
- Use English inventory roles `perimeter`, `internal` and `lab` (0.x used `perimetr` and `interni`).
- Name the Compose project `netops`; additional instances need an explicit `docker compose -p`.
- Report role configuration failures using fixed schema fields and reason codes without echoing input values; preserve useful reasons when input contains short words or schema names.
- Import Auditor snapshots and validated policies into private persistent state using create-only names; require a durable operator intent before reading import input.
- Write Auditor SARIF output privately (mode 0600) and refuse links or foreign files as the output path.
- Use digest-pinned Linux images for amd64 and arm64; qualify exact distribution bytes before the user's personal signature.
- Known 1.0 syslog limitation: audit records up to 8 MiB plus framing exceed the RFC 5425 minimum interoperability baseline. Receivers may truncate or discard oversized messages; default settings do not guarantee complete audit. Use explicitly configured rsyslog 8.2512 gtls with `maxMessageSize="9m"` and imtcp `MaxFrameSize="9437184"`; see [Syslog delivery](docs/architecture-1.0.md#syslog-delivery). General interoperability with default RFC-compliant receivers requires a later build.
- Known 1.0 limitation: there is no supported provisioning path for the schema registry/library files of Helper `schema_read` and `fortios_diagnostics`, the extra input files of advanced Auditor `--suppressions`, `merge-sarif` and `schema-check`, or file-based Admin offline/schema workflows. See [Helper configuration](docs/helper-configuration.md), [Auditor workflows](docs/quickstart-1.0.md#auditor-operator-workflows) and [Admin workflows](docs/admin-configuration.md).
