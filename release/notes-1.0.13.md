NetOps 1.0.13 follows NetOps 1.0.12. It updates the runtime and MCP dependencies, adds FortiOS tables to Admin and requires the approved preview hash for every Admin apply, makes the container memory limit configurable, and simplifies the documented upgrade procedure.

## Changes in 1.0.13

- Admin refuses preview and apply for profiles without documented live write and return evidence. See the [disabled profiles and firmware coverage](../docs/admin-configuration.md#live-verification-required-for-admin-profiles).
- Admin manages more FortiOS 7.6.8 tables: DHCP servers and their address ranges, the system DNS servers (opt-in), the syslog settings, service groups, recurring and one-time schedules, IPv6 address objects, IPv6 address groups and opt-in IPv6 static routes. Every Admin apply now requires the `plan_sha256` of the approved preview (MCP `expected_plan_sha256`, CLI `--expect-plan-sha256`) on every platform and table; without it the apply is refused before the device is contacted. Undo checks the identity of the object first and refuses to remove an object that was replaced outside Admin. If an enabled firewall policy matches an IPv6 address or group, directly or through nested groups, changes that affect the match require `endpoint_impact`. As a known limitation, Admin refuses address and group membership changes if it finds references outside group membership or `firewall policy` IPv6 matches; for example, a `local-in-policy6` reference blocks the change even through nested groups. Admin refuses creating or editing an IPv6 address object at `::/0` and deleting such an object, because saving or restoring it requires interactive confirmation on the device. Admin also refuses every change to the IPv6 default route `::/0` as a routing safeguard. To change other IPv6 static routes, use an IPv4 literal for Admin's device address and for its reachability-check address if configured separately. On FortiOS 8.0.1 and later the new tables are refused before any write. See the [FortiOS operations added in 1.0.13](../docs/admin-configuration.md#fortios-operations-added-in-1013).
- The runtime uses Python 3.15.2 on Alpine 3.24. The pinned dependencies include FastMCP 4.2.4, MCP 2.3.0, Starlette 1.10.0, Uvicorn 0.54.0, and PySNMP 7.1.33. The MCP endpoint uses HTTPS.
- Set `NETOPS_MEMORY` in `.env` to change the container memory limit. The default is `1g`. The documented host minimum is 2 vCPUs, 2 GiB of RAM, and 2 GiB of disk space.
- FortiOS and FortiADC SSH require the enrolled OpenSSH public key in `host_key`, matching `host_key_fingerprint`. For the Auditor, this applies to FortiOS SSH collection. It evaluates FortiADC exports.
- Helper keeps Linux IPv4 route records when iproute2 prints extra attributes such as `nhid`, `mtu`, `advmss` or `table`.
- The Auditor evaluates Cisco IOS and IOS XE, Cisco NX-OS, Arista EOS and Juniper Junos configurations from a file or a pinned SSH collection, and has more FortiOS and ExtremeXOS rules. A rule that relies on a default the device does not print is evaluated only when the collection proves the complete output; otherwise the rule is `not-evaluated` with its reason, and the coverage lists evaluated and not-evaluated rules. Give site-specific expectations as `audit_intent`; `auditor import-policy` imports them for every platform except FortiADC. The Auditor tools `audit_status`, `list_rules`, `rule_detail` and `findings_summary` accept an optional `platform`. See the [Auditor channels](../components/netops-auditor/docs/channels.md) and the [management-policy reference](../components/netops-auditor/docs/management-policy.md#audit-intent).
- The new Helper tool `network_overview` returns a paginated operational snapshot of enrolled FortiGate devices (including observations of managed FortiSwitches and FortiAPs where available), ExtremeXOS, Cisco IOS, IOS XE and NX-OS, Arista EOS, Juniper Junos, Ruckus Unleashed, FortiADC and Linux targets. Each device reports its read coverage and the reasons for any partial result. The default call budget is 45 seconds (configurable from 5 to 120 seconds), with up to four concurrent targets, 10 seconds per read and 30 seconds per target. Without `limit`, a page holds at most four targets and uses one parallel round under the shared 45-second default budget; if time runs out, the response reports incomplete coverage. See the [tool guide](../components/netops-helper/docs/network-overview.md).
- The product exposes 50 MCP tools (32 Helper, 8 Auditor and 10 Admin), or 40 with Admin disabled. See the [MCP API change declaration](acceptance/api-changes-1.0.12-1.0.13.json).
- To upgrade, back up the immediately preceding version, install the new version in a clean instance, restore the backup, and verify the restored instance. See the [upgrade procedure](../docs/quickstart-1.0.md#upgrade-from-the-previous-release).

The classifier replay baseline (`components/netops-helper/tests/fixtures/output_status_baseline.json`) holds 1102 captured texts.

## Acceptance

The acceptance of 1.0.13 runs once on the release candidate image before the maintainer signs: the Actions candidate checks, the installation by following the quickstart on the [supported platforms](../README.md#supported-platforms), `release/acceptance/upgrade-check.sh` from 1.0.12 to 1.0.13 against `release/acceptance/api-changes-1.0.12-1.0.13.json`, and the MCP client acceptance with Codex CLI and Claude Code. Its results are the acceptance reports (`acceptance-*.json`) covered by the signed checksum list. The client results are added to this section with the release; until then this section asserts no acceptance result. The latest documented client results are those of [NetOps 1.0.12](notes-1.0.12.md#acceptance).
